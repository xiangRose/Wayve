# 微任务设计参考（发给设计 / 内容同学）

> 不用看原始爬取 JSON。本文档已从 56 条 JD 样本归纳，够用来设计 5–7 分钟的微任务情境。

## 设计微任务需要什么数据？

| 需要 | 不需要 |
|------|--------|
| 岗位做什么（definition） | 56 个 raw 文件全文 |
| 真实工作片段（typicalWorkSnippet） | aggregated 里的 JSON 结构 |
| 痛点与取舍（painPoints） | 后端 API 字段 |
| 1 个具体产品情境 + 冲突 | 每岗 15 条 JD 都读完 |

**结论：** 微任务设计看 **归纳结果 + 情境想象力**，不是堆 JD 数量。  
Hackathon Demo 每岗 **1 个完整微任务** 即可；`ai_product` 已有范例（见 `seed/task-templates/ai_product.career_changer.json`）。

## 五岗速查（设计情境时直接抄）

### ai_product · AI产品（interactive，优先做完）

- **一句话：** 定义 AI 产品方向，在用户需求、技术可行性与业务目标间做优先级判断。
- **工作片段：** 有限资源下权衡需求与技术，定义方向并协调团队落地。
- **痛点：** 跨部门协调、需求变更、技术落地难、用户反馈杂。
- **情境灵感：** 注册涨但留存跌；新功能上线争议；研发只能做一件事。
- **参考 JD：** 微信读书 AI 产品经理、微信输入法 AI 产品策划、王者荣耀 AI 工具方向策划

### ai_ui_design · AIUI设计（interactive，优先做完）

- **一句话：** 把复杂 AI 能力做成可理解、可操作的界面与交互。
- **工作片段：** 平衡用户需求与技术限制，输出交互方案并推动落地。
- **痛点：** 多方改稿、方案反复、需求变化快。
- **情境灵感：** 新用户不知从何点起；AI 回答慢/不确定如何展示；功能堆叠导致首页混乱。
- **参考 JD：** 字节 AI-native UX Designer、游戏 UI 设计

### ai_ops · AI运营（preview，可先写骨架）

- **一句话：** 用数据与策略推动 AI 产品增长、留存与反馈闭环。
- **工作片段：** 协调产品、算法、业务，让运营策略真正落地。
- **痛点：** 跨团队沟通、策略执行难、用户反馈处理。
- **情境灵感：** 渠道带来大量新用户但首次有效使用率低；活动数据好但留存没涨。
- **参考 JD：** 微信小店生态治理产品运营、大模型 Agent 策略产品运营

### ai_data_eval · AI数据与评测（preview）

- **一句话：** 设计评测体系，判断模型/功能是否达标并推动迭代。
- **工作片段：** 自动评测 vs 人工评测取舍；资源有限时如何定通过标准。
- **痛点：** 数据质量、标准对齐难、跨团队扯皮。
- **情境灵感：** 上线前「好不好」吵不停；bad case 激增不知先修哪类；标注质量参差。
- **参考 JD：** 微信大模型评测产品经理、小微对话效果与评测

### ai_app_dev · AI应用开发（preview）

- **一句话：** 把大模型能力做成可交付应用，在效果、成本、延迟间取舍。
- **工作片段：** 资源有限时优化系统性能，同时满足多方业务需求。
- **痛点：** 跨职能协作、性能调优、技术债与迭代压力。
- **情境灵感：** 要加智能总结但响应慢成本高；RAG 召回差 vs 延迟高；流式输出与降级策略。
- **参考 JD：** 腾讯大模型 Agent 应用研发、豆包方舟解决方案架构师

## 微任务结构（跟 ai_product 范例对齐）

每岗建议 **5 步、约 7 分钟**：

1. **进入情境** — 给背景数据 + 用户原声，让用户用一句话说清矛盾
2. **初步判断** — 单选 + 简短理由（先猜方向）
3. **主动取证** — 从 3–4 条信息里选 1–2 条查看（考察会不会找证据）
4. **新证据出现** — 推翻或强化先前判断（考察会不会调整）
5. **决策与下一步** — 在资源约束下给出可验证的下一步

**禁止用语：** 「最适合」「适配潜力」「推荐你从事」  
**改用：** 「本轮证据」「值得继续体验」「你在 X 方面表现出较多支持证据」
